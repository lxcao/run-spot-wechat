## D1. 上线形态（最重要，决定整套架构）

| 选项 | 工作量 | 体验 | 推荐度 |
|---|---|---|---|
| **B. H5 链接直接丢群 + Vercel/Cloudflare Pages 静态托管** | 1~2 天 | ★★★★ | ⭐⭐⭐⭐⭐ |
| A. 认证服务号 + 备案域名 + 自定义菜单 | 2~3 周 | ★★★★★ | ⭐⭐⭐（投入大） |
| F. 飞书多维表格 / 腾讯文档先试水 | 1 小时 | ★★ | ⭐⭐（过渡） |
| D. 微信小程序 | 1~2 月 | ★★★★★ | ⭐（投入大） |

**我的建议**：先走 B 把 MVP 跑起来，跑通了再加 A。

## D2. 数据存储

| 选项 | 工作量 | 维护成本 |
|---|---|---|
| **JSON 文件 + GitHub 仓库（Cloudflare Pages 自动部署）** | 极低 | 群主学一下 GitHub 网页编辑 |
| Cloudflare KV / Vercel KV（在线编辑 + 部署） | 低 | 群主改 KV 控制台 |
| Supabase / Cloudflare D1（带 SQL 表） | 中 | 群主用表单页编辑 |
| Notion API（Notion 当数据库） | 中 | 群主在 Notion 写 |

**我的建议**：先 JSON 文件 + Git，跑通后再升级到 KV。

## D3. 群主发布方式

| 选项 | 群主成本 |
|---|---|
| **直接改 GitHub 网页上的 JSON 文件** | 每次 1 分钟 |
| 一个独立 admin 页（Cloudflare Pages + 简单密码） | 每次 30 秒 |
| 公众号菜单的"发布活动"入口（输入参数） | 每次 1 分钟 |
| Notion 表格反向同步 | 每次 30 秒 |

**我的建议**：v1 让群主改 JSON + Git push（Cloudflare Pages 自动部署）。v2 再加 admin 页。

## D4. 跑友报名是否要

| 选项 | 说明 |
|---|---|
| **不要** | 仅展示活动信息，跑友无需注册 |
| 简单 yes/no | 记录"X 人确认参加"，用于统计 |
| 完整报名（昵称 + 人数） | 需要登录，跑友体验差 |

**我的建议**：v1 不做。群主继续在群里发接龙。

## D5. 是否要推送（活动当天提醒）

| 选项 | 工作量 |
|---|---|
| **不要** | 跑友周六早上自己看群 |
| 服务号模板消息 | 个人主体不支持，企业需认证 + 模板审核 |
| 群机器人推送 | 需要企微或 Hook 协议（风险大） |

**我的建议**：v1 不做。群里群主发提醒。
