# Run Spot WeChat — 产品简报

> 一个面向上海跑团的微信群内应用：
> 让跑友在微信里一键看到本周/未来活动的集合点、时间、星巴克位置，
> 并能回看历史活动（路线、集合点、照片）。

---

## 1. 用户故事（来自真实场景）

- **小李（跑友）**：周五看到群里接龙 "周六早上 7:30 世纪公园"。他想确认集合点具体是公园几号门、地铁几号口出来、旁边的星巴克是哪家。他打开群里的链接，看到一张地图 + 集合点 pin + 一键高德导航。
- **王姐（群主）**：每周五要在群里发接龙 + 公告。她希望在公众号后台或一个简单表单里填好"日期/时间/集合点/星巴克/备注"，发布后自动生成一个可分享的群链接，状态变更（如取消、延期）能自动通知群。
- **老张（新跑友）**：刚被拉进群。他想看历史——这个跑团都去过哪儿、平均配速、跑步路线、大家合影。他打开应用的历史标签，看到一份时间线 + 路线回顾。

## 2. 核心使用流程

```
每周四~五：
  群主在后台（或群里 @机器人 / 命令）发布活动 → 生成 unique 链接
  群主将链接丢到跑团群
  跑友点击链接 → 看到本周活动卡片（时间/集合点/星巴克/路线）
  跑友在应用里点"我要参加" → 报名名单更新
  跑友点"导航去星巴克" → 调起高德
  跑友点"导航去集合点" → 调起高德

活动当天早上：
  跑友在群里收到集合提醒（公众号模板消息 / 群机器人）

活动结束后：
  群主上传照片、回填路线、统计人数
  历史活动列表自动归档
```

## 3. 功能边界（v1 必须有 / v2 可以有 / v3 想要）

### v1 — MVP（最小可用，2~4 周）

| 功能 | 必要性 | 说明 |
|---|---|---|
| 查看本周活动卡片 | ✅ 必须 | 时间、地点、星巴克、备注 |
| 集合点地图（继承 amap-trip-planner） | ✅ 必须 | 高德瓦片 + pin + 一键导航 |
| 历史活动列表 | ✅ 必须 | 时间倒序，至少 5 条 |
| 历史活动详情 | ✅ 必须 | 复用本周活动卡片模板 |
| 群主发布活动 | ✅ 必须 | 表单（最简：在线填 JSON） |
| 跑友报名（仅计数） | 🟡 可选 | 不强求，可省 |
| 公众号菜单入口 | 🟡 可选 | 直接丢链接也能用 |
| 数据存储（活动 + 历史） | ✅ 必须 | 见方案对比 |

### v2 — 增强

- 跑友报名确认（带昵称、人数）
- 活动结束后照片墙（OSS / 腾讯云存储）
- 一键导出跑步路线 GPX
- 跑团成员主页（累计公里数 / 参加次数）
- 推送提醒（公众号模板消息 / 服务号）

### v3 — 长期

- 跑步成绩（接 Apple Health / 微信运动）
- 跑团排行榜
- 装备拼团 / 团购
- 私约约跑

## 4. 非功能要求

- **零运维**：群主不应该需要懂服务器。可托管到 Serverless 平台。
- **微信内可用**：所有页面在微信内置浏览器打开必须流畅。
- **移动优先**：iPhone 6 (375pt) 起可用，地图可拖、可放大。
- **数据可迁移**：活动数据应该是开放格式（JSON / Markdown），群主可以随时导出。
- **隐私最小化**：跑友昵称 + 微信头像 opt-in 才收集，不上传通讯录。

## 5. 不做什么（v1 明确砍掉）

- ❌ 跑步打卡 / GPS 轨迹记录（用 Keep / 咕咚）
- ❌ 社交 Feed / 关注
- ❌ 私信 / 评论
- ❌ 商品交易
- ❌ 复杂权限 / 多跑团管理（只服务你一个跑团）
