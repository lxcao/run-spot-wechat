# 微信群内应用的可行性分析

> 目标：跑友在微信群聊窗口里点击链接 → 直接看到跑团活动信息。
> 这一节对比所有可行的技术路径，列出每条的优缺点 + 必备条件 + 工作量。

---

## 总览：微信生态中的"群内打开应用"实现路径

| # | 路径 | 形态 | 工作量 | 必备条件 | 适合谁 |
|---|---|---|---|---|---|
| A | **H5 网页 + 公众号菜单** | 服务号菜单 → H5 网页 | 中 | 认证服务号 + 备案域名 + ICP | 想长期运营的跑团 |
| B | **H5 网页 + 直接分享** | 网页链接丢群里 | 低 | 一个 https URL | 临时/低成本 |
| C | **H5 网页 + 短链 + 二维码** | 长链转短链，群机器人推送 | 低 | 短链生成服务 | 想美化链接的 |
| D | **微信小程序** | 小程序卡片 | 高 | 注册小程序 + 上架审核 | 体验要求高 |
| E | **企业微信群机器人** | 群里 @机器人发卡片 | 中 | 企业微信 | 已经用企微的 |
| F | **第三方平台挂靠** | 腾讯文档 / 飞书多维表格 / Notion 页 | 极低 | 注册对应账号 | 完全不想写代码 |

---

## 详细分析

### A. 公众号菜单 + H5 网页（推荐）

**形态**：服务号自定义菜单 "📍本周活动" → H5 页面。群主更新活动后，在群内丢菜单链接即可。

**优势**
- 微信内浏览器完美支持，地图可拖动、JS 可调用、Amap JS API 可直接用
- 群友在公众号里也能搜到历史活动
- 可订阅消息推送（提醒群友活动当天）

**必备条件**
1. **认证服务号**（不是订阅号！）— 订阅号没有自定义菜单
   - 主体：个人 / 企业均可，但个人订阅号功能受限
   - 费用：企业认证 300 元/年，个人免费但功能受限
   - 时间：注册 + 认证约 3~7 天
2. **备案域名**（用于 HTTPS + 业务域名）
   - 必须 ICP 备案，国内服务器
   - 业务域名配置：公众号后台 → 设置 → 公众号设置 → 功能设置 → 业务域名 + JS 接口安全域名
   - 域名解析 + SSL 证书（HTTPS 强制）
3. **部署平台**：推荐腾讯云轻量 / 阿里云 / Cloudflare（CNAME 接入需备案）

**工作量**
- 前端 H5（基于 amap-trip-planner 模板改造）: 3~5 天
- 后端 API + 数据存储: 3~5 天
- 群主发布表单: 1~2 天
- 联调 + 上线: 2~3 天
- **总计**：约 2~3 周（如果你熟悉），否则 1 个月+

**风险**
- 个人主体的服务号不能开通模板消息推送（v2 想做推送时会卡住）
- 备案域名走完流程至少 1~2 周（如果你没域名）

---

### B. 直接分享 H5 链接（最快上线）

**形态**：把 HTML 部署到任意 HTTPS URL，群主手动复制粘贴到群。

**优势**
- **零门槛**：只要一个 https URL 就行
- 域名可以是境外（不用备案）：Cloudflare Pages / Vercel / Netlify / GitHub Pages
- 部署 5 分钟完成

**必备条件**
1. 一个 GitHub / Cloudflare / Vercel 账号（免费）
2. 域名可选：用平台提供的 `*.vercel.app` / `*.pages.dev` 子域名也行，但微信可能拦截陌生短域（实测 Vercel/Cloudflare 子域名目前可访问）

**工作量**
- 把 amap-trip-planner 的 HTML 模板改成"跑团专用模板"
- 活动数据用 URL 参数或单独的 JSON 文件驱动
- **总计**：1~2 天就能跑起来

**风险**
- 微信偶尔会拦截外部短域（提示"该网页可能存在风险"），需要用户手动复制到浏览器
- 国内访问 Vercel/Cloudflare 慢
- 群主每次发布活动要改数据文件 + 重新部署（或用一个简单 Web 表单）

**这是 MVP 推荐路径** —— 用 Cloudflare Pages 或 Vercel 部署静态 H5，数据用一个简单的 JSON 文件，跑通了再升级到 A。

---

### C. H5 + 短链 + 群机器人

**形态**：群机器人（Wechaty / 企业微信机器人 / iPad 协议）监听群里 "发布活动" 命令 → 自动生成短链 → 推到群里。

**优势**
- 群主不用手动复制粘贴
- 群里点链接 + 短链美观

**必备条件**
1. 同 B 的所有条件
2. 群机器人：Wechaty 风险大（封号）；企业微信机器人需要企业微信；Hook 协议基本不能商用

**不推荐** —— 风险高，性价比低。

---

### D. 微信小程序

**形态**：用户在小程序卡片里看活动。

**优势**
- 体验最原生：可调用 wx.getLocation、wx.openLocation 跳转高德
- 可以用"微信小程序云开发"省掉后端部署
- 群分享支持"小程序卡片"标题/缩略图，比裸链接美观

**必备条件**
1. **小程序账号 + 主体**：个人可注册但功能受限；企业主体可上"工具 > 跑团"类目
2. **类目审核**：跑团相关类目可能归到"体育"或"生活服务"
3. **SSL 域名**：小程序后端 API 仍需 https
4. **首次发布审核**：7 天左右，后续更新 1~3 天
5. 包大小限制 2MB；不能引用外网 CDN（要用 npm 或内置包）

**工作量**
- 学 WXML / WXSS / 小程序 API: 5~7 天
- 重写地图组件（不能用 Leaflet，要用小程序原生 map + 腾讯/高德 SDK）
- 后端对接
- **总计**：3~4 周（小团队），个人 2 个月+

**风险**
- 类目审核可能被拒（"工具类目不能有社交/打卡"）
- iOS 端高德 SDK 调用没有 H5 顺滑

**不推荐 v1** —— 投入产出比太低。等跑团粉丝数破百再考虑。

---

### E. 企业微信机器人

**形态**：跑团迁到企业微信群，跑团机器人推送活动卡片。

**优势**
- 企业微信机器人 API 公开，无封号风险
- 群内可发富文本卡片（标题 + 描述 + 跳转链接）

**必备条件**
1. 企业微信账号（免费注册企业）
2. 自建应用机器人

**风险**
- 跑友不一定接受企业微信（需要新装 App）

**推荐度：低** —— 除非你跑团已经用企微。

---

### F. 第三方平台挂靠（最快，但不"原生"）

**形态**：
- 方案 F1：腾讯文档 / 飞书多维表格 → 在文档里写活动信息 → 群内丢链接
- 方案 F2：Notion 页 → 分享给群友

**优势**
- 完全零代码，群主直接在文档里写
- 腾讯文档有现成的"活动模板"
- 飞书多维表格可以加投票/收集表

**必备条件**
1. 腾讯文档 / 飞书账号（个人版免费）
2. 一个能写"时间/地点/路线/星巴克"的模板

**风险**
- 不是"应用"，更像电子公告牌
- 没办法一键高德导航
- 跑友体验差（看到的是表格/文档，不是网页）

**推荐度：中** —— v0 阶段如果你只是想试试，可以先飞书/腾讯文档把跑团信息结构化，验证大家真的看这些信息；之后再升级到 B 或 A。

---

## 推荐路径

**MVP（v1）**：**B. 直接分享 H5 链接 + Vercel/Cloudflare Pages 静态托管**
- 投入：1~2 天
- 域名：平台免费子域名（如 `run-spot-wechat.pages.dev`）
- 数据：JSON 文件 + Git 版本管理
- 群主流程：在 GitHub 网页上改 JSON → 自动部署 → 复制新链接到群

**升级（v2）**：**A. 认证服务号 + 备案域名 + 自定义菜单**
- 投入：2~3 周
- 推送能力 + 更专业的入口
- 数据：加一个轻量后端（Cloudflare Workers / 腾讯云函数）

**长期（v3）**：根据实际规模决定是否做小程序

## amap-trip-planner 的复用情况

amap-trip-planner 是**单次地图工具**，输出一个本地 HTML。需要做这些改造：

| 原 amap-trip-planner | 改造后 run-spot-wechat |
|---|---|
| 1~N 个 POI | 1 个集合点 + 1 个星巴克（固定 2 pin） |
| 输入是 POI 名称 | 输入是活动 ID（从 JSON 读） |
| 单 HTML 文件 | 单 HTML 文件 + URL 参数 `?event=<id>` |
| 没有历史 | 主页 → 列表 → 详情两级 |
| 没有导航首页 | 主页 = 即将开始的活动卡片 + 历史时间线 |

可以**完全复用**的：
- Leaflet + 高德瓦片渲染（assets/map-template.html 90% 复用）
- uri.amap.com 导航跳转逻辑
- geocode.py 脚本（仅需在后台运行，烤进 JSON 数据）

需要**新增**的：
- 活动数据 JSON schema
- 多页（主页 / 详情）路由（URL hash + JS 切换）
- 群主发布表单（最简：Web 上一个表单页）
- 数据写入逻辑（v1: GitHub API 自动 commit / v2: 真实数据库）

## 必备条件清单（按推荐路径 B）

### 群主侧（你）
1. [ ] 一个 GitHub 账号（如果你已经有）
2. [ ] 注册 Cloudflare 账号，启用 Pages（免费）
3. [ ] 准备 5~10 个常用活动数据（JSON 格式）
4. [ ] 高德 Web Service API Key（已有，amap-trip-planner 在用）

### 跑友侧
- 无需任何操作，微信里点链接即可

### 跑团侧
- 群主每周花 2 分钟改 JSON + 部署（或更简单：用 Cloudflare 提供的 KV 直接在线编辑）

### 外部依赖
- Cloudflare Pages：免费层无限流量 / 无限请求
- 高德 Web Service API：免费层 5000 次/天（足够）
- 高德 JS API / 瓦片：地图直接走 `webrd0*.is.autonavi.com`，免费

## 待用户确认的关键决策

详见 `02-DECISIONS.md` 的待选项。

最关键三个：
1. **上线形态**：B（直接分享） vs A（服务号菜单） vs F（飞书文档先试水）
2. **数据存储**：JSON + Git vs 简单 KV（Cloudflare KV / Vercel KV）vs 正式数据库
3. **群主发布方式**：手改 JSON + Git push vs 在线表单页 vs Notion API 反向同步
